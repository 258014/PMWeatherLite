# PMWeatherLite 优化评估报告（v1 → v2）

> 评估日期：2026-11-18。对象：`E:\mc_pack_work\PMWeatherLite\`（Forge 1.20.1）
> 方法：逐行审查每 tick 热路径 → 定位性能/稳定性/边界问题 → 针对性修改 → 重新编译验证。
> 结论：**7 类实质问题已修复，编译 BUILD SUCCESSFUL，jar 从 25→26 class / 60→63KB。**
> 说明：本报告的性能倍数为**基于代码路径的静态估算**（本环境无血缘存档/真实玩家压测条件），
> 标注为"估算"，不冒充实测帧率。

---

## 一、审查范围与方法

审计了主循环全部 7 个每 tick 调用的系统、热力学核心、天气系统、粒子与破坏逻辑，
重点看三类问题：
- **性能**：每 tick 的分配、重复计算、无节流的重计算、网络同步频率；
- **稳定性**：状态机覆盖、内存泄漏、与其他 mod 抢主导权；
- **边界**：空玩家、重复触发、判断对象错误、维度卸载。

## 三、关键改进（已实施）

### 3.1 性能

**P1 — 天气同步从"每 tick"改为"仅状态变化时"**
- 加入 `lastRaining`/`lastThundering`/`initialized` 三态缓存；
- 只有当目标天气状态与上次实际写入不同时才调用 `setWeatherParameters()`。
- 效果（估算）：空闲/无风暴时网络同步包从 **20 次/秒/玩家 → 0**；有风暴时也只在切换瞬间发 1 次。
- 附带收益：不再每 tick 覆盖天气计时器，自然天气循环恢复，降低与其他 mod 抢主导权的概率。

**P2 — 降水相态缓存 + 人数自适应**
- 相态（依赖昂贵的 buildProfile）改为**按 64 格网格缓存 5 秒**（`phaseCache`，带过期淘汰）；
- 粒子数按在线人数分档（>8 人降到 2 档，>3 人 3 档，否则 4 档）防止拥挤时粒子风暴。
- 效果（估算）：`buildProfile` 调用从 **10 次/秒/玩家 → 0.2 次/秒/64格列**，约 **50× 下降**（单玩家持续站在风暴区的稳态）。

**P3 — 热力学噪声提升出循环**
- `lrNoise`/`columnNoise`（bump 与逆温共用一个采样点）原本每层重复算，现在循环外算一次；
- 预计算 `bumpH`/`bumpStrength`/`inversionHeight`/`invScale`，循环内只保留真正依赖高度的 3D `tNoise`。
- 效果（估算）：单次 buildProfile 的噪声采样从约 **128 次 → 36 次**（32 层 × 4 vs 32 × 1 + 4），约 **3.5× 加速**。

**P4 — 破坏扫描节流**
- 龙卷破坏扫描从每 tick 改为**每 5 tick（4 次/秒）**，破坏观感不变但 CPU 降约 80%；
- 保留了方块级风控，视觉连续性与破坏力不受明显影响。

### 3.2 稳定性

**P5 — 打通 18 种天气的完整链路（本次最重要修复）**
- `WeatherStateBridge` 现在消费 WeatherSystem 事件：`precipitationAtFirstPlayer()` + `hasThunderstormNearPlayers()`；
- `PrecipitationSystem` 现在同时读取 WeatherSystem 的降水；
- 新增 `/pmwlite status` 查看活动事件数，`/pmwlite clear` 同时清两套系统。
- 效果：之前 `/pmwlite weather TORNADO` 几乎只有内部状态；现在会真实驱动天空转雨、闪电、降水粒子。

**P6 — 维度卸载清理**
- 新增 `LevelEvent.Unload` 监听，卸载时移除对应 level 的 StormManager/WeatherSystem，消除泄漏。

### 3.3 边界

- **P7**：`surfaceDew` 复用已算好的 temp，去掉重复 biome 查询与 pow；
- **P8**：野火改为检查 `FIRE.defaultBlockState().canSurvive(level, p.above())` 且要求实体支撑；
- **P9**：`clear` 命令同时清 WeatherSystem。

## 五、仍存在的问题（未解决 / 部分解决）

1. **无真实压测**：本环境无存档与多玩家条件，所有性能数字为静态估算；建议实机用 Spark/TickProfiler 验证。
2. **两套天气系统并存**：StormManager（4 类风暴）与 WeatherSystem（18 类事件）逻辑上仍有功能重叠，
   长期应统一到一个管理器，避免重复降水/风场计算。
3. **相态缓存的空间键**：按 64 格网格缓存，跨越网格边界时相态可能突变（5 秒延迟），视觉上偶有跳变。
4. **`level.random` 共用**：天气判定消耗世界随机序列（P10 未改），跨版本/跨 mod 的存档复现性有细微影响；
   建议改用独立 `RandomSource`。
5. **降水粒子非真实物理**：当前雨/雪/雹用原版粒子 + 简单速度，冰雹的"落地弹跳"未完全实现（简化为快速下落）。
6. **热浪/寒潮/沙尘的"体感"**：仅驱动温度代理与粒子，未接入玩家 debuff（中暑/冻伤/呼吸道），缺少玩法层面影响。
7. **音效缺失**：龙卷警报、雷声定位、风声未移植，沉浸感弱于原版 PMWeather。
8. **雷达/风速计方块**未实现，18 种天气缺少"观测/预警"的道具层。
9. **CAPE 抬升曲线简化**：`liftedParcelTemp` 用干绝热 + 粗略 moist 修正，未精确求 LCL/LFC/EL，
   CAPE 数值为近似，风险门控可能与真实大气略有偏差。
10. **光影依赖**：不开光影时体积云缺席，观感明显弱化（这是兼容光影架构的固有取舍，非 bug）。

## 六、下一步优化建议（按优先级）

**P0 — 立即（低成本高收益）**
1. 用 Spark 做一次真实 profile，确认 buildProfile 与扫描是否仍是热点，用实测替换本文估算。
2. 把 `level.random` 换成独立的 `RandomSource.create(level.getSeed() ^ 0xPMW)`，消除 P10。
3. 给相态缓存改用双线性/邻域混合，消除跨网格跳变。

**P1 — 短期（架构收敛）**
4. 统一两套天气系统：让 WeatherSystem 成为唯一事件源，StormManager 降级为"龙卷物理执行器"，
   消除重复降水/风场计算。
5. 补齐玩法影响：热浪/寒潮给玩家加 debuff（Namespace 自定义 MobEffect），沙尘降能见度 + 呼吸伤害。
6. 龙卷破坏加"每方块冷却表"，避免同一区块被反复卷起导致地形过度破坏。

**P2 — 中期（体验补齐）**
7. 移植精简音效系统（警报/雷声/风声），用 `SoundEvent` + 距离衰减。
8. 用 KubeJS + Blockbench 做雷达/风速计方块，给 18 种天气一个"可观测"的入口。
9. 冰雹落地弹跳与积雪堆积：用 falling block + 方块堆积，替代纯粒子。

**P3 — 长期（精度与规模）**
10. 引入二次曲线精确求解 LCL/LFC/EL，提升 CAPE 风险门控的物理保真度。
11. 客户端预测与网络优化：天气事件用自定义 packet 同步，减少服务端轮询。
12. 分级_config 化：把 18 种天气的半径/稀有度/持续做成 data pack 可配置，便于整合包作者调平衡。
