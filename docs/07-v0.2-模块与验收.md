# v0.2 模块清单与验收标准

> 版本：0.2.0 · 目标：在**不破坏 v0.1 公开接口 / 数据结构 / 调用方式**的前提下，补齐音效与雷达 GUI、
> 后处理管线与光影兼容层、天气预报机与预警机制、固定资产物体。

## 0. 兼容性基线（先立规矩）

v0.2 **只做加法**。下面这些 v0.1 的公开面一行未改，签名、字段、语义、默认值全部保持：

| 类型 | 位置 | 状态 |
|---|---|---|
| `PMWLite.MOD_ID` / `LOGGER` | `PMWLite` | 未变 |
| `StormManager` 公开方法（`tick` `getStorms` `getWind` `summonAt` …） | `weather.StormManager` | 未变 |
| `WeatherSystem` / `WeatherEvent` 字段与 `trigger` `clearAll` `getActive` | `weather.WeatherSystem` | 未变 |
| `WeatherType`（18 个常量 + 字段 `coreRadiusBlocks` / `outerRadiusBlocks` …） | `weather.WeatherType` | 未变 |
| `Thermodynamics.Profile` / `buildProfile` / `formationRisk` / `instability` | `weather.Thermodynamics` | 未变 |
| `ServerConfig` 全部开关（`doDamage` …）+ `strengthThreshold(BlockState)` | `config.ServerConfig` | 未变 |
| `SoundManager.Sfx` 枚举与 `playUi` / `toggleMute` / `forget` | `sound.SoundManager` | 未变 |
| `/pmwlite summon` `weather` `list` `status` `mute` `clear` | 命令树 | 行为未变（仅实现改为走 `stormManager()` 访问器） |

**唯一的行为差异**：`TornadoDestroyHandler` 在计算阈值时多加了两项——
`IFixedAsset` 免疫判定与 `FortificationManager.bonusAt()`。
当服务器上没有任何加固、没有任何固定资产时，`bonusAt()` 恒为 0、`instanceof` 判定恒为假，
破坏结果与 v0.1 **逐方块一致**。

## 2. 逐模块：实现范围 / 不做的事 / 验收标准

### 模块 A — 音效

**实现范围**
- `ModRegistry` 注册 10 个 `SoundEvent`：`storm_ambient` `tornado_roar` `hail_tick`
  `alert.blue` `alert.yellow` `alert.orange` `alert.red` `radar.ping` `station.scan` `fortify.apply`。
- `assets/pmwlite/sounds.json` 用 `"type": "event"` 把每个事件**指向已存在的原版事件**，
  因此 jar 内**不含任何 `.ogg`**（体积 0 KB、无音频授权问题），但每个事件都能被资源包单独替换/静音。
- `lang/zh_cn.json` + `en_us.json` 提供字幕与物品名。

**不做的事**：不新增音频素材、不改 `SoundManager.Sfx` 的既有映射。

**验收标准**

| 编号 | 判据 | 验证方式 |
|---|---|---|
| A1 | 10 个 `sounds.json` 键与 `ModRegistry` 注册 id **逐一对应**，无遗漏无多余 | 脚本比对（见 §4.1） |
| A2 | 引用的原版事件 id 真实存在于 `SoundEvents` | 常量池比对：9/10 命中，`ambient.weather.rain` **实测不存在**，已修正为 `weather.rain` ✅ |
| A3 | 客户端播放不报 `Unable to play unknown soundEvent` | 实机；资源加载失败仅跳过播放，不崩 |

> 实测记录：在 `forge-1.20.1-47.2.0` 的 `SoundEvents.class` 常量池中逐条比对，
> 现存 1.20.1 的雨天环境音 id 是 `weather.rain` / `weather.rain.above`，`ambient.weather.rain` 已不存在。
> 该条已按实测结果改正——这正是"先验证再写死"的价值。

### 模块 B — 雷达 GUI

**实现范围**
- 服务端 `RadarService.sendTo(player)` 汇总 3 类目标：风暴（kind 0）、天气事件（kind 1）、固定资产（kind 2），
  半径 512 格，附带预报（等级/风险/ETA/置信）+ 加固计数，打成**一个** `RadarSyncPacket`。
- 线格式：`varint` 编码，实测 **132 字节**（2 个天气类型 + 3 个 blip）。
- 客户端 `ClientRadarCache` 只做缓存 + 陈旧判定（>2.5 s 标"数据过期"）。
- `RadarScreen`：程序化生成 128×128 环形刻度贴图（`DynamicTexture`，不打包 PNG），
  绘制 4 道距离环、十字线、30° 刻度、旋转扫描线、按 kind 着色 blip、右侧信息栏。
- `ClientSetup` 注册按键 `key.pmwlite.radar`（默认 **R**，`KeyConflictContext.IN_GAME`），
  界面打开期间 1 Hz 自动刷新；`/pmwlite radar` 可手动推送一次。

**不做的事**：不做 3D 雷达、不做鼠标悬停详情、不缓存历史轨迹。

**验收标准**

| 编号 | 判据 | 验证方式 |
|---|---|---|
| B1 | 编解码**逐字段无损**，且无残留字节 | 往返测试（§4.2）：16 个字段 + 3 个 blip × 6 字段全部相等，`readableBytes()==0` ✅ |
| B2 | 无玩家/无权限时命令**安全失败**而不抛异常 | 服务器控制台执行 `/pmwlite radar`：仅输出"只能由玩家执行" ✅ |
| B3 | 雷达数据与服务端状态同源，不额外模拟 | `RadarService` 只读 `getStorms()` / `getActive()` / `FixedAssetManager.all()` |
| B4 | GUI 在光影开/关两种配置下都能显示 | 全部走 `GuiGraphics`（2D 管线），与后处理无关 |

### 模块 C — 后处理管线 + 光影兼容层

**这是"修复移植后视觉差异"的主战场**，做法是**分层 + 让路**，而不是抢占管线。

**实现范围**

1. `ShaderCompatLayer`：识别 `oculus` / `iris` / `optifine`，反射读取当前光影包名（`Iris.getCurrentPackName()`），
   20 tick 节流探测，输出 `Mode`：
   `VANILLA` / `IRIS_NO_PACK` / `SHADER_PACK_ACTIVE` / `OPTIFINE_SHADERS`。
   三个能力开关：`postEffectsAllowed()`（光影在则 false）、`fogEventsAllowed()`（同上）、`overlayAllowed()`（恒 true）。
2. `PostEffectPipeline`：真正的 `PostChain` 全屏 pass。
   - 关键难点：`PostChain` 的 passes 是私有的，从 JSON 载入的链**无法逐帧改 uniform**，效果会被冻结。
   - 解法：链 JSON 只声明**目标**不声明 pass（`"passes": []`），再用公开的
     `addPass(name, in, out)` 自己把 pass 加进去并**拿回 `PostPass` 句柄**，从而能
     `getEffect().safeGetUniform("StormHaze").set(...)`。
   - 两趟：`pmwlite:storm_haze`（main→temp，雾霾+暗角+去饱和+闪电）→ `pmwlite:storm_blit`（temp→main 写回）。
   - 顶点着色器**不使用 `ProjMat`**（直接 `Position.xy / OutSize → NDC`），
     避免依赖渲染器残留的投影状态，这是抗"黑屏"的关键设计。
3. `AtmosphereLayer`：`ViewportEvent.RenderFog` 拉近远平面、`ComputeFogColor` 向板岩灰/雪白偏色。
   只作用于 `FOG_TERRAIN` 且 `FogType.NONE`，绝不干扰水/岩浆/细雪。
4. `StormOverlayLayer`：`RenderGuiEvent.Post` 上做暗角、雨幕条纹、闪电白闪、右上角强度徽标。
   光影在时**主动放弃**雨幕与闪光（避免与光影的"双份雨"），只保留暗角。

**不做的事**：不做 raymarching 体积云（那是光影包的工作，也是原版 mod 与光影冲突的根因）。

**验收标准**

| 编号 | 判据 | 验证方式 |
|---|---|---|
| C1 | 光影包生效时，本 mod **不触碰**后处理链 | `postEffectsAllowed()` 返回 false 时 `render()` 首行即 return |
| C2 | 后处理任何失败都**不崩、不黑屏**，且自动回退 | `render()` 全程 `try/catch(Throwable)` → `disabled=true` + 只记一次日志；雾/叠加层仍生效 |
| C3 | 资源重载后管线重建，不持有已删除的 GL 对象 | `RegisterClientReloadListenersEvent` → `PostEffectPipeline.invalidate()` |
| C4 | 视觉差异被补齐且可关 | 三层各自可独立关闭：`/pmwlite fx off`（后处理）、`/pmwlite hud off`（叠加层） |
| C5 | 着色器/程序资源路径与引擎解析规则一致 | 反编译核对：program→`assets/<ns>/shaders/program/<name>.json`；shader→`assets/<ns>/shaders/core/<name>.{vsh,fsh}`；链→构造参数**原样**当路径用，必须给全 `shaders/post/x.json` ✅ |

> C5 是实测出来的一个坑：`PostChain` 构造器把入参直接交给 `getResourceOrThrow`，
> **不做** `shaders/post/` 前缀拼接，所以必须传完整路径。这一条已按字节码修正。

### 模块 D — 天气预报机 + 预警

**实现范围**
- `ForecastEngine`：复用 `Thermodynamics.buildProfile` + `formationRisk`（**与风暴生成同一套公式**），
  64 格网格 × 200 tick 缓存；`etaFromStorms()` 对 800 格内风暴按 10 m/s 保守速度估算。
  输出 `Forecast(alertLevel, risk, etaTicks, headline, expectedTypes, confidence, precise)`。
- 四级预警阈值：`0.35 / 0.65 / 0.95 / 1.25` → 蓝 / 黄 / 橙 / 红。
- `AlertManager`：每 20 tick（1 Hz）扫一遍玩家；
  **升级立即播报**、**≥黄色每 30 s 提醒一次**、**降级静默**；橙色以上额外写聊天框。
  音效用 A 模块的四个 alert 事件，随等级改变音高。
- `WeatherStationBlock`（天气预报机）：右键输出四行预报；放在原位即把
  `FixedAssetManager.STATION_COVERAGE = 256` 格内的 `precise` 置真、置信 +10%。

**不做的事**：不做雷达回波图、不做多日预报。

**验收标准**

| 编号 | 判据 | 验证方式 |
|---|---|---|
| D1 | 分级边界严格按阈值 | 逻辑测试（§4.3）：0/0.34/0.35/0.64/0.65/0.94/0.95/1.24/1.25/1.75 → 0/0/1/1/2/2/3/3/4/4 ✅ |
| D2 | 预警"提前"而非事后 | ETA 由**风险值**与**风暴距离**两条独立路径给出，风暴尚未生成时也能出蓝/黄 |
| D3 | 无玩家时不空转、不报错 | `tick()` 首行 `level.players().isEmpty()` 直接返回；服务器实测无异常 ✅ |
| D4 | 玩家退出后不泄漏 | `onPlayerLogout` → `AlertManager.forget(uuid)`；地图 128 上限兜底裁剪 |
| D5 | 控制台调用不崩 | 控制台跑 `forecast`：`getPlayer()` 为空时退化为按坐标计算 ✅ |

### 模块 E — 固定资产

**实现范围**
- `IFixedAsset` 接口：`assetId()`、`windThreshold()`（默认 -1 = 免疫）、`onRegistered/onUnregistered`。
- `FixedAssetManager`：**按维度**登记的 `Map<BlockPos, AssetRecord>`（不是 BlockEntity）。
  理由写在类注释里：既有系统（破坏扫描 / 雷达 / 覆盖判定）全部按坐标工作，v0.1 也没有任何 BlockEntity；
  用位置表可以让这些调用点**零改动**接入，也不需要 NBT 迁移。上限 512，`pruneInvalid()` 自清理。
- `WeatherStationBlock`：`onPlace` 登记、`onRemove` 注销、`windThreshold() = -1`（风暴中照样工作）。
- `ReinforcementKitItem`（加固套件）：右键任意方块 → `FortificationManager.fortify()`，
  每级 +15，上限 +60，每级消耗 1 点耐久（64 次）。
- `FortificationManager`：`Map<BlockPos, Integer>`，上限 8192，`bonusAt()` 未加固时返回 0。
- `TornadoDestroyHandler` 接入：`threshold + bonusAt(pos)`，破坏时同步 `release()` 与 `unregister()`。

**不做的事**：不给方块加 blockstate / NBT（保证"兼容现有物体管理逻辑"）。

**验收标准**

| 编号 | 判据 | 验证方式 |
|---|---|---|
| E1 | 加固线性可叠加、到顶拒绝、可释放 | 逻辑测试（§4.3）：0→15→30→45→60→`-1`；`release` 后回 0、计数归零 ✅ |
| E2 | 未加固/无资产时破坏行为与 v0.1 一致 | `bonusAt()` 恒 0、`instanceof` 恒假 → 阈值与判定路径不变 |
| E3 | 固定资产不被误删、注销及时 | `onPlace`/`onRemove` 成对；`pruneInvalid()` 兜底；破坏路径显式 `unregister` |
| E4 | 数量上限生效，不会无限增长 | `MAX_ASSETS=512` / `MAX_ENTRIES=8192`，超限返回 false / -1 并给出提示 |
| E5 | 维度卸载后状态清空 | `LevelEvent.Unload` → `FixedAssetManager.clear` / `FortificationManager.clear` / `ForecastEngine.clear` ✅ |

## 4. 实测记录

### 4.1 资源一致性

- `sounds.json` 10 个键 ↔ `ModRegistry` 10 个 `SoundEvent`：一一对应。
- 引用的原版事件名在 `SoundEvents.class` 常量池中比对：**9 个直接命中**，`ambient.weather.rain` 不存在 →
  改为 `weather.rain`（同一次比对确认 `weather.rain` / `weather.rain.above` 存在）。

```
alertLevel/risk/etaSeconds/confidence/precise/headline/types
blip[0..2].kind/dx/dz/radius/intensity/code
```


### 4.4 专用服务器端到端（Forge 1.20.1-47.2.0，flat 世界）

用一个 `load` 函数在开服时依次执行：

```
pmwlite list / summon / weather SUPERCELL / weather TORNADO / status
pmwlite forecast / assets / reinforce / radar / hint
```

随后 200 s 内每 10 s 再跑一次 `status` / `forecast` / `assets`。

结果：
- `PMWeather Lite initialized` + `Done (3.216s)!` + `PMWeather Lite ready … 18 weather types.`
- 连续 **200 秒**、双风暴 + 双天气事件同时运行；
- `[SMOKE] 200-ticks-alive` 20 次全到；
- **0 条** `com.stellar` 相关异常、**0 条** ERROR、**0 次** `Can't keep up`。

这覆盖了 `StormManager.tick` / `WeatherSystem.tick` / `TornadoDestroyHandler` / `WeatherStateBridge` /
`TornadoFX` / `PrecipitationSystem` / `WildfireSystem` / `AlertManager.tick` / `ForecastEngine`（含缓存刷新）/
`FixedAssetManager` / `FortificationManager` 的整条服务端链路。

### 4.5 字节码核对（防止"凭记忆写 API"）

| 结论 | 依据 |
|---|---|
| `PostChain` 构造入参是**完整资源路径** | 构造器 `load()` → `resourceManager.getResourceOrThrow(入参)` |
| 空 `passes` 数组安全 | `load()` 仅在 `isArrayNode("passes")` 时迭代，空数组直接跳过 |
| 能拿到 `PostPass` 句柄 | `public PostPass addPass(String, RenderTarget, RenderTarget)` |
| uniform 可在 `process()` 前设置 | `PostPass.process` 先 `set(...)` 再 `effect.apply()`（缓冲式 uniform） |
| 顶点格式属性名 | `DefaultVertexFormat.POSITION` + 程序 JSON `attributes:[{"name":"Position"}]` |
| 资源路径规则 | `EffectInstance` → `shaders/program/`；`ShaderInstance` → `shaders/core/` |

## 6. 已知限制

1. **观感只能在实机确认**：本文档能证明"管线接对了、失败会回退、光影在时让路"，不能证明"好看"。
   后处理的强度参数（`StormHaze` 系数 0.55、暗角 0.62）是保守取值，建议实机按光影包微调。
2. **光影包内的雨雾不受本 mod 控制**：Iris 自己算雾，本 mod 主动让路；差异只能靠叠加层与粒子弥补。
3. **加固不持久化**：`FortificationManager` 是内存表，重启后清零（与 v0.1 的天气状态一致）。
   如果需要持久化，属于 v0.3 的 NBT/Codec 工作。
4. **天气预报机的贴图使用原版材质占位**（`models/block/weather_station.json` 复用原版方块纹理），
   自绘材质留待美术资源。
5. **雷达不显示风暴旋转方向与移动矢量**：只给位置、半径、强度，够用但不炫技。
