# 光影与后处理联动（渲染层改动说明）

> 本轮只改**客户端渲染**：新增一份光照状态快照，让雾、后处理 pass、2D 合成层读同一份光；
> 明确一帧里各阶段的先后顺序；把阴影四参数接进已有的那一个 pass。
>
> **不动**：服务端模拟、网络包、天气/大气场、光影包的所有权、pass 数量（仍是 2）。
> 本轮改动在 v0.3.0 之后的工作区里，未单独发版。

---

## 1. 一帧里的阶段与先后顺序

以前代码里只有一句"fog → post → overlay"，没有说明三个阶段内部谁先谁后。
现在把顺序固定下来，改 shader 时按这张表推演：

| # | 阶段 | 代码位置 | 作用 | 光影包生效时 |
|---|---|---|---|---|
| 0 | 客户端 tick | `ClientEvents.onClientTick` → `LightingState.tick()` | 算一次光照/阴影快照（20 Hz） | **照常**（只读) |
| 1 | 雾距 | `ViewportEvent.RenderFog` → `AtmosphereLayer.applyFog` | 地形 shader 内部拉近 far/near plane | 让路（Iris 自算雾） |
| 2 | 雾色 | `ViewportEvent.ComputeFogColor` → `AtmosphereLayer.applyFogColor` | 天空色 × 降水核色 | 让路 |
| 3 | **Stage A** 空气光 | `storm_haze.fsh` A 段 | 太阳屏幕方向的前向散射 | 整条 pass 让路 |
| 4 | **Stage B** 阴影幕 | `storm_haze.fsh` B 段 | 强度/软化/分辨率/偏移 | 整条 pass 让路 |
| 5 | **Stage C** 风暴雾 | `storm_haze.fsh` C 段 | 去饱和、对比保持 | 整条 pass 让路 |
| 6 | **Stage D** 闪电 | `storm_haze.fsh` D 段 | 色温随日光走 | 交给光影包 |
| 7 | **Stage E** 暗角 | `storm_haze.fsh` E 段 | 黄昏暖边 | 用 2D 暗角代替 |
| 8 | 拷贝回主缓冲 | `PostPass #2 storm_blit`：temp → main | 恢复主缓冲可读 | 整条 pass 让路 |
| 9 | 2D 合成 | `RenderGuiEvent.Post` → `StormOverlayLayer` | 光照幕 → 暗角 → 雨幕 → 闪电 → HUD | **照常** |

**Stage A~E 写在同一个 fragment 里，不是五个 pass。** 它们处理同一个像素，
拆开只会多四次全屏采样。整条链始终只有两个 pass：

```
main ──[storm_haze]──▶ temp ──[storm_blit]──▶ main
```

## 2. 新增的唯一状态源：`LightingState`

一个 tick 算一次，渲染路径只读静态 float（零分配）。所有量都从原版时间/天气派生，
**没有新网络包，也不读服务端状态**——单机、联机、光影包下得到同样的光。

### 光照

| 参数 | 范围 | 来源 | 影响 |
|---|---|---|---|
| `sunlight` 日光强度 | 0..1 | `1−skyDarken`，再被雨/雷削弱（雨 ×0.55、雷 ×0.20，下限 0.18） | Stage A 散射亮度；B 段阴影强度 |
| `sunX/Y/Z` 太阳方向 | 单位向量 | `getSunAngle()`：0=日出、π/2=正午 | 投到相机空间得到 `screenSun*` |
| `screenSunX/Y/Facing` | −1..1 | 太阳向量点乘相机 right/up/forward | xy 决定散射/阴影方向，z>0 表示太阳入镜 |
| `sunR/G/B` 日光色 | 0..1 | 正午近白，晨昏插到 (1, 0.64, 0.36) | 散射色、闪电色、暗角暖边 |
| `ambR/G/B` 环境色 | 0..1 | **原版 `level.getSkyColor()`** | 雾色基线、暗部反弹光、2D 幕颜色 |
| `ambient` 环境强度 | 0..1 | 天空亮度 × 白昼系数 | 阴影里的反弹光幅度 |
| `daylight` / `dusk` | 0..1 | `getSkyDarken()` / 太阳高度角 | 控制天气核权重、暗角暖边、阴影存在感 |

### 阴影（屏幕空间幕四参数）

| 参数 | 范围 | 怎么算 | 视觉影响 |
|---|---|---|---|
| `shadowStrength` 强度 | 0..0.85 | `0.12 + 0.55 × sunlight` | 直接乘进暗部衰减（最多 ×0.70），越大越沉 |
| `shadowSoftness` 软化 | 0.06..0.45 | `0.10 + dusk×0.22 + rain×0.12 + thunder×0.05` | Stage B `smoothstep` 的边缘宽度；太阳低/下雨越糊 |
| `shadowResolution` 分辨率 | 固定 96 | 常量 | 暗部量化的网格数；抖动幅度 = 1/grid，越大越细腻（代价不变） |
| `shadowOffsetX/Y` 偏移 | 约 ±0.006 | `−screenSun.xy × 0.006` | 暗部相对太阳反向偏移；转视角时跟着世界走，不像贴纸 |

> **重要**：这里的 `shadowResolution` 是**我们自己的屏幕空间阴影幕量化网格**，
> 不是 Iris/OptiFine 的 `shadowMapResolution`。本 mod 从不写光影包的 uniform——
> 那是它的所有权，抢了就会黑屏/冲突。我们只保证自己的合成层跟它的光照同步。

## 3. 关键实现点

### `LightingState`（新文件，client 包）

- 唯一写入点 `tick(float)`：`ClientEvents.onClientTick` 每 tick 调一次，位于
  `ShaderCompatLayer.tick()` 与 `ClientVisualState.tick()` 之后。
- `reset()`：无世界（菜单/切维度）时给中性读数，避免显示层读到上一维度残留。
- 每 tick 有几个小 `Vec3` 临时对象（MC 的 `getSkyColor`/`getViewVector` 与相机叉积），
  20 Hz 下远低于每帧分配的路径；**渲染回调里零分配**。
- `/pmwlite fx light` 只读打印当前快照，便于对比参数改动前后。

### `PostEffectPipeline`

- 每帧重写 15 个 uniform（含原有 4 个），与风暴强度同源；
  `OutSize` 在窗口尺寸变化后会自动重建，不会留旧值。
- 任一名拼错 → `safeGetUniform` 返回 null → 按既有设计整条管线回退到雾 + 叠加层，不会黑屏。
- **pass 数、目标数、渲染分辨率都没变**：`pmwlite_haze` 仍是唯一 temp target。

### `storm_haze.fsh`

- Stage A 前向散射：`pow(max(dot(viewDir,sunDir),0),3) × max(SunScreen.z,0)`；
  太阳在镜头背后时不加光，避免"背对太阳却画面发亮"。
- Stage B 阴影幕：`floor()` 量化 + 格内 hash 抖动，软化宽度由 `ShadowSoftness` 控制；
  动量只在 `texCoord + ShadowOffset` 上偏移，不采深度纹理，**因此不会和光影包的阴影贴图打架**。
- Stage C 雾色基线从写死的板岩灰改为 `AmbientColor`（权重 `0.30×Daylight`）：
  夜晚暗、雪原亮，白天仍以降水核为主。
- Stage D 闪电色温随 `SunColor` 走，黄昏闪暖白而不是冷白。
- Stage E 顺手修正原来 `smoothstep(0.80, 0.28, d)` 的反向边界（GLSL 未定义行为），
  改为 `1.0 − smoothstep(0.28, 0.80, d)`，结果一致但合法。

### `AtmosphereLayer` / `StormOverlayLayer`

- 雾色：基色取天空色，白昼天气核权重 0.35→0.80；夜晚不会"发光的灰雾"。
- 雾距：在风暴缩减之上再乘 `1−shadowStrength×0.06−dusk×0.05`（下限 0.89），幅度很小。
- 新增 `lightVeil()`：6 条极淡的 2D 带（alpha ≤18，即 7%），
  在光影包激活、3D pass 让路时仍能把"低太阳/软阴影"传达到画面底部；
  方向与 Stage B 共用 `shadowOffset`，两边不会各走各的。
- 暗角/闪电颜色都改为从环境色/日光色派生，不再全场景一个蓝灰。

## 4. 参数影响速查（调参时先看这里）

| 想改什么 | 改哪里 | 副作用 |
|---|---|---|
| 风暴天太暗 | `PostEffectPipeline` 里 `ShadowStrength` 的系数 / fsh 中 `veil*0.30` | 太亮会丢掉"厚重空气"的层次 |
| 阴影边缘太硬/太糊 | `LightingState.shadowSoftness` 基础值 0.10 与 `dusk/rain` 权重 | 超过 0.45 会变成整屏渐变 |
| 阴影有横带 | 提高 `shadowResolution`（96→128）或增大 hash 抖动 `1/grid` | 网格越细越像平滑渐变 |
| 散射太亮 | fsh `air*0.32` 或 `Sunlight` 的雨衰减 0.55 | 晴天入镜时会发白 |
| 黄昏不够暖 | `LightingState` 中 `sunG/sunB` 的终端值 (0.64/0.36) | 过暖会像滤镜 |
| 雾太近 | `AtmosphereLayer.lightScale` 的 0.06/0.05 | 主缩放仍在 `ClientVisualState.fogScale()` |
| 光影包下太暗 | `StormOverlayLayer.lightVeil` 的 alpha 上限 18 | 这是唯一在包下仍生效的自定义层 |

## 5. 回归注意事项

### 必须验证

1. **无光影（VANILLA / IRIS_NO_PACK）**：`/pmwlite fx status` 显示后处理运行中；
   晴天→暴雨→雷暴，雾色、暗角、前向散射应当连续变化；`storm_haze` 不黑屏、不闪面。
2. **光影包激活（SHADER_PACK_ACTIVE）**：`/pmwlite fx status` 必须显示
   "交由光影处理"，3D pass **完全没有运行**；旋转视角时 2D 光照幕只有轻微跟随，
   不得出现双份雨幕、双份闪电或整屏压黑。
3. **时段边界**：`time set 0 / 6000 / 12000 / 18000` 各看一次，
   确认夜晚不出现发光灰雾、黄昏散射偏暖、正午不过曝。
4. **窗口缩放**：改分辨率后 `OutSize` 重建，暗角网格不应拉伸或错位。
5. **资源热重载**：`/reload` 后 pass 应能重建；若失败必须回退到雾+叠加层而不是黑屏。
6. **15 个 uniform 一致性**：改 shader 时同时改
   `PostEffectPipeline.java`、`program/storm_haze.json`、`core/storm_haze.fsh` 三处；
   本轮已用脚本校验三方名字完全一致。

### 不变量（别破坏）

- pass 数 = 2，temp target 数 = 1，不新增网络包，不读写服务端状态。
- `ShaderCompatLayer.postEffectsAllowed()` 仍是 3D pass 的唯一总闸；
  `fogEventsAllowed()` 仍是雾的唯一总闸。
- 不写 Iris/OptiFine 的任何内部 uniform；光影包继续拥有自己的后处理链。
- 原版 `rain`/`thunder` 驱动方式未改，光影包对该状态的响应保持原样。

### 已知限制

- 屏幕空间阴影幕是**风格化近似**，不采样深度贴图，所以它不会与地形起伏精确对齐；
  真实阴影仍由光影包（或原版太阳方向光）负责。
- 低配 GPU 上全屏 fragment 的 hash + smoothstep 仍有成本；
  已经把五个阶段合并在一个 pass 里，若仍吃紧，先降 `shadowResolution` 并不能省时间
  （计算量与网格数无关），应通过 `/pmwlite fx off` 整条关闭。
