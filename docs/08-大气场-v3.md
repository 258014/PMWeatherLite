# v0.3 大气场：把天气从「掷骰子」变成「可求解的物理场」

> 目标来源：《大气层重构》（RimWorld mod，作者 Acutus）——文章的核心不是"更多天气类型"，
> 而是**换掉模拟范式**：
>
> - 「每一格都有一份空气。它从高压流向低压，绕过墙壁、穿过门，混合热量与水汽，甚至，因为科里奥利力而些微旋转」
> - 「本地地图新增 10 个图层，显示风、风场流线、气压、地面温度、体感温度、湿度、氧气含量、土壤含水量」
> - 「一个完整的、包含如此多物理量耦合的流体力学求解器，加上八层的仿真全球气候模拟」
>
> v0.1 / v0.2 的天气是"实体"：一个 Storm 对象带着 Rankine 涡旋在世界里飘，天气类型由
> 噪声 + 概率决定。v0.3 改成"场"：玩家周围的空间被切成格子，**每格独立持有一份空气**，
> 每 3 tick 解一次方程，所有下游逻辑（破坏、降水、HUD、雷达）都从这个场里读数。

---

## 1. 总体结构：三层，各管一个尺度

| 层 | 类 | 分辨率 | 步长 | 管什么 |
|---|---|---|---|---|
| 全球环流 | `GlobalModel` | 8×8 列 × **8 层**（10 m → 16 km） | 20 tick | 气压/温度/湿度/云/风的三维气候态，风暴引导气流 |
| 本地大气 | `AtmosphereGrid` | 16×16×8 格（每格 16×16×48 方块，覆盖 256×256×384） | 3 tick | 逐格空气：p / u,v,w / q / T / O₂ / 云量 |
| 地形风 | `TerrainWind` | 逐列（16 格） | 10 tick 缓存 | 遮蔽、狭管加速、卡门涡街 |

三层是**同一套量在不同尺度上的两次求解**：全球层给出大尺度背景（地转风、引导气流），
本地层在这个背景上解细节（浮力、平流、质量守恒），地形层是本地层的近地面边界条件。

调度器 `AtmosphereManager` 负责：玩家重心搬运网格、节流、给 HUD/雷达/破坏逻辑提供统一查询入口。
**没有玩家时不计算**——大气场是"观测窗口"，不是世界状态，没人看的时候不该烧 CPU。

## 2. 本地大气网格 `AtmosphereGrid`

### 2.1 状态量

每格 8 个 `float`，全部是一维 `float[2048]`（无对象、无装箱）：

| 量 | 单位 | 说明 |
|---|---|---|
| `p` | hPa | 气压，由静力学积分得到 |
| `t` | ℃ | 气温 |
| `q` | g/kg | 比湿 |
| `o2` | 体积比 | 氧气（0.2095 = 海平面标准） |
| `u` `v` `w` | m/s | 三维风 |
| `cloud` | 0..1 | 云水量（可降水云） |

另有 4 个双缓冲数组（`tN/qN/o2N/cloudN`）供半拉格朗日平流写入，1 个 `phi` + 1 个 `div` 供
速度投影使用。列状态（`surfaceY/groundT/water/fire`）各 256 个。

### 2.2 单步的六件事

```
step(gameTime, baseWind, rainLevel):
  1. refreshFireColumns   滚动扫描火源（每步 32 列，8 步一轮）
  2. applySurfaceForcing  地面热惯性、水面蒸发、火源加热耗氧、敞口格氧气交换
  3. updatePressure       静力学积分：p(y) = p_sfc · exp(−g·h / (R·Tv_mean))
  4. applyBuoyancy        虚温异常 + 水汽浮力 → 垂直速度 w
  5. advect               半拉格朗日平流（无条件稳定，允许大时间步）
  6. swap                 平流结果"转正"——**必须在 7~10 之前**
  7. applyMomentum        −∇p/ρ + 大尺度底风松弛 + 地面摩擦 + 科氏偏转
  8. project              红黑超松弛解 ∇²φ = ∇·u，u/v/w ← u/v/w − ∇φ
  9. relaxMoisture        过饱和成云（凝结放热）、降水补水汽、云被降水清除
 10. clampFields          物理区间裁剪
```

> **踩过的坑**：最初 `swap()` 放在最后。平流写的是 `tN/qN/...`，而 `applySurfaceForcing`、
> `relaxMoisture` 写的是 `t/q/...`，于是每一步结束时"旧的当前值"会把刚算出的强迫项覆盖掉——
> 地表加热、火源耗氧、凝结成云全部**静默失效**，而场本身看起来完全正常（无 NaN、无量级异常）。
> 表现就是"云量永远 0%"。自检里的"降水条件下能成云"这一条就是为了钉住这个错误。

### 2.3 三个值得单独说的点

**（1）气压不是常数场——静力学积分**

v0.2 的"气压"只是个查询用的理想值。这里每步用虚温廓线重新积分：

```
Tv = T · (1 + 0.608·q)                      // 虚温：湿空气比干空气轻
p(y) = p_sfc · exp(−g·h / (R·Tv_mean))      // h = (y+0.5)·48 m
p_sfc = 1013.25 − (T_ground − 15)·0.12      // 暖区略低（热低压）
```

于是"暖而湿的气柱高层气压偏高、冷气柱反之"自动成立——这就是热成风，
也是 `applyMomentum` 里 `−∇p/ρ` 的真正来源。**风与气压变成双向耦合**，不是各算各的。
代价：128 列 × 8 层 = 1024 次 `exp` / 步，实测可忽略。

**（2）速度投影要连 `w` 一起修正**

只修正 u/v 是常见的偷懒做法：散度只被压掉三分之二，垂直运动仍会"凭空生风"。
这里三个分量一起投影，投影后的平均散度见验收表。

**（3）半拉格朗日平流的边界**

`sample()` 越界时按最近格取值（等价于开放边界），而不是夹到 0——这样气流进出网格不会被
人工边界反射回来形成驻波。

### 2.4 查询接口

```java
boolean probe(double wx, double wy, double wz, Probe out)   // 三线性插值，不分配
float   columnCloud(double wx, double wz)                   // 整列云量最大值
float   groundTempAt(double wx, double wz)
float   waterFraction()
```

`Probe` 是**复用容器**：一次采样填充 11 个派生量（露点、体感、云底、风速、是否地下），
调用方传自己的容器进来，热路径上零分配。云量走 `columnCloud` 而不是探针——云长在空中，
玩家站的那一层往往云量接近 0，判断"该不该下雨"必须看整根气柱。

## 3. 地形风 `TerrainWind`

真实近地面风会被地形和建筑强烈改写。三种效应，都是按列查高度图，不做逐方块遮挡：

| 效应 | 判据 | 结果 |
|---|---|---|
| 遮蔽 shelter | 沿来流方向 2..14 格内存在比自己高的地形 | 0.15 ~ 0.95（越近挡得越狠） |
| 狭管 venturi | 两侧（垂直来流方向）都高于自己 1.5 格且来流方向通 | ×1.45 |
| 卡门涡街 wake | 背风 2..8 格 | ±0.28·(1−d/10)·sin(2π·t/120) |
| 暴露度 exposure | 高于地表 2 格 / 0.5 格 / 贴地 | ×1.18 / ×1.06 / ×0.92 |

最终 `factor = shelter × venturi × exposure`，破坏判定里 `windSpeed ×= factor × (1 + gust)`。

**接线点**：`TornadoDestroyHandler.ripAroundFunnel`。每列采样一次（约 49 次/扫描），
不进逐方块热循环；结果按 (x,z) 缓存 10 tick，上限 4096 条。

关掉 `terrainWind` → 该乘法整体跳过，破坏行为与 v0.2 逐位一致。

## 4. 八层全球环流 `GlobalModel`

8×8 列 × 8 层 = 512 格，每 20 tick 一步。层高与命名：

| 层 | 高度 | 名称 |
|---|---|---|
| 0 | 10 m | 近地面 |
| 1 | 300 m | 边界层顶 |
| 2 | 900 m | 低层云 |
| 3 | 2000 m | **中层（引导气流）** |
| 4 | 4000 m | 高层云 |
| 5 | 7000 m | 对流层顶 |
| 6 | 11000 m | 平流层下部 |
| 7 | 16000 m | 平流层上部 |

### 4.1 三件事让它不只是装饰

1. **地转风**：`u_g = −∂p/∂z /(f·ρ)`、`v_g = ∂p/∂x /(f·ρ)`。
   Minecraft 没有纬度，这里把 **z 坐标当纬度**（−80°..80°），于是南北向移动时偏转真的会变：
   热带（z≈0）几乎没有偏转，中纬才有；北半球西风、南半球东风。
2. **赤道—极地温差**：`surfT −= 38 · (|lat|/80)²`。
   没有这一项，同一种生物群系铺满全场时气压梯度恒为 0，全球风也恒为 0——
   "全球环流"就成了空壳。真实大气的第一驱动力正是这个温差。
3. **热成风**：气压场由温度场按测高公式积分，上层风切变（高空西风急流）自己长出来。
4. **风暴注入**：每个风暴当作暖心低压按高度加权压进气压场（近地面 −22 hPa、+3.5 ℃），
   于是风暴周围的等压线、辐合、引导气流都是**算出来的**。

### 4.1.1 为什么需要一个量级标定 `GEO_SCALE`

一个格子 512 格（方块），而真实天气系统的水平尺度是 1000 km 量级。把同样的气压差摊在
512 m 上，地转公式会算出 **5000 m/s** 的"急流"，全部撞到 70 m/s 的裁剪上限——方向对，但没有层次。

所以乘一个 `0.003` 的标定系数：中层回到 10~40 m/s、近地面 5~20 m/s，
**方向与相对强弱完整保留**，这正是我们要它做的事（给风暴一个合理的引导气流），
而不是去精确复现地球自转速度。这是"尺度失真下的工程折中"，不是物理常数。

标定后实测：中层 ≈ 20 m/s 西风、近地面 ≈ 10 m/s、风暴附近叠加 30~70 m/s 的环流——
和真实探空的量级对得上。

### 4.2 风暴真的被它推着走

`StormManager.tick()` 里新增：

```java
if (cfg.globalSteering && cfg.doAtmosphere) steer(s);
// 每 tick 只修正 1%，目标 = 中层引导气流 × 55%
s.velocity += (steeringWind × 0.55 − s.velocity) × 0.01
```

配合 Storm 自带的 0.985 阻尼，风暴会在十几秒内平滑转到引导气流方向，而不是瞬移。
取 55% 是因为真实风暴移速通常只有 700 hPa 风速的一半左右。

## 5. 体感温度与氧气 `ApparentTemperature`

不用拍线性系数，直接用两套官方经验公式：

| 量 | 公式 | 适用区间 |
|---|---|---|
| 风寒 Wind Chill | `13.12 + 0.6215T − 11.37v^0.16 + 0.3965T·v^0.16`（NWS 2001） | T ≤ 10 ℃ 且 v > 4.8 km/h |
| 热指数 Heat Index | Rothfusz 回归（NWS） | T ≥ 27 ℃ |
| 露点 | Magnus 反解 | 全区间 |
| 云底 LCL | `125 × (T − T_d)` | 全区间 |
| 饱和比湿 | `622 · e_s/(p − 0.378·e_s)`，`e_s` 用 Magnus | 全区间 |

两者都只依赖 T / v / RH 三个量，正好是网格里已有的字段，不引入任何额外状态。

**低氧后果**（可关）：氧气 < 0.145 给挖掘疲劳，< 0.085 每 2 秒 1 点溺水伤害。
数值只做提示，不做惩罚性秒杀；创造/旁观免疫。

## 6. 雷达图层与观测 HUD

雷达 GUI（`R`）从 v0.2 的单张降水图扩成 **7 个图层**，`1`..`7` 或 `←/→` 切换：

| # | 图层 | 单位 | 数据源 |
|---|---|---|---|
| 1 | 降水/云量 | % | `columnCloud`（整列最大云量） |
| 2 | 气压 | hPa | `probe.pressureHpa` |
| 3 | 气温 | ℃ | `probe.tempC` |
| 4 | 相对湿度 | % | `probe.humidity` |
| 5 | 氧气 | % | `probe.oxygen` |
| 6 | 风场 | m/s + 箭头 | `probe.windSpeed` / `atan2(v,u)` |
| 7 | 体感温度 | ℃ | `probe.apparentC` |

采样平面取玩家视线高度，16×16 格，量化成 `byte`（NaN = 实心地形 → 画成透明，
所以地下挖洞时雷达上会出现真实形状的空洞）。

**与文章 10 图层的对照**：文章列了「风、风场流线、气压、地面温度、体感温度、湿度、氧气含量、土壤含水量」等。
本轮做了其中 7 个（云量/气压/气温/湿度/氧气/风/体感），**没有做**的是：

| 缺的图层 | 为什么本轮没做 | 补的话要动哪里 |
|---|---|---|
| 风场流线 | 需要客户端沿风场做流线积分（逐像素回溯），是渲染工作量，不是物理工作量 | `RadarScreen` 加一条流线积分循环，数据用现有的 `aux` 角度 + 速度即可 |
| 土壤含水量 | 需要一个按列的水量收支状态（降水下渗 / 蒸发 / 径流）并反馈到蒸发率 | `AtmosphereGrid` 加 `soil[256]`，在 `applySurfaceForcing` 里改成"蒸发率 ∝ 土壤含水量"，再加第 8 个图层 |

地面温度已经可从 `groundTempAt()` 取到，但没单独做图层——它和气温图层高度相关，
再单开一层信息增益不大。

网络：`AtmosLayerPacket`（一层一包，约 300 B）、`AtmosProbePacket`（44 B，1 Hz）。
`PROTOCOL` 从 `"1"` 升到 `"2"`——旧客户端不会收到新包，新客户端连旧服务端会握手失败并提示，
不会静默错位。

HUD 常驻两行读数（气压/气温/体感/云底、风/氧气/湿度），氧气低于阈值时追加 `⚠ 空气稀薄`。

## 7. 云量驱动降水

`PrecipitationSystem` 原来只看降水强度。现在额外乘一个云量因子：

```
mod = clamp(columnCloud / 0.45, 0.08, 1.0)
```

云薄时只落零星雨点，云厚时不衰减。下限 0.08 是为了避免"雨声在响但没雨滴"的割裂感。
`cloudDrivenPrecipitation=false` 或 `doAtmosphere=false` 时整段跳过，与 v0.2 逐位一致。

`ServerConfig` 新增 5 个布尔：

| 开关 | 默认 | 关掉之后 |
|---|---|---|
| `doAtmosphere` | true | 完全不建场、不发包、不算氧，行为 = v0.2 |

| `oxygenEffects` | true | 只显示数值，不给 debuff |
| `cloudDrivenPrecipitation` | true | 降水粒子数不随云量变 = v0.2 |

`/pmwlite` 只新增 `atmos`、`global`、`atmoscheck` 三个子命令。

## 9. 自检：把物理不变量变成可执行断言

`/pmwlite atmoscheck [steps]`（控制台也可执行，网格按命令位置临时建立）：

| # | 断言 | 为什么需要它 |
|---|---|---|
| 1 | 本地网格建立成功 | 高度图/生物群系读取是否正常 |
| 2 | 稳态单步耗时 < 1500 µs | 性能预算，防止某次改动悄悄变慢 |
| 3 | 无 NaN/Inf | NaN 会污染后续每一步 |
| 4 | 场值在物理区间 | p∈[300,1100] hPa、T∈[−90,70] ℃、q∈[0,60] g/kg、O₂∈[0,0.3]、\|u,v\|≤60、w∈[−25,30] |
| 5-6 | 气压 / 温度有空间变化 | 防止场退化成常数 |
| 7 | 气压随高度严格递减 | 静力学平衡 |
| 8 | 平均散度 < 0.5 s⁻¹ | 质量守恒（弱形式） |
| 9-12 | 探针可取值 / 露点≤气温 / 云底≥0 / 湿度·氧气区间 | 派生量不能自相矛盾 |
| 13-14 | **降水条件下能成云** / 云量 ≤ 100% | 钉住"强迫被 swap 覆盖"这一类静默失效 |
| 15-19 | 全球模型就绪 / 八层气压递减 / 风速≤70 / 地转风非零 / 引导气流可取 | 全球层不是空壳 |
| 20-25 | 风寒、热指数、露点、饱和比湿、往返一致、云底 | 六个参考点对上教科书值 |
| 26-29 | 风暴存活 / 无 NaN / 移速合理 | 接线不断、不超速 |

### 9.2 自检抓到的三个真实缺陷

这一节是本轮最有价值的部分——三个问题都**不会**在"能跑起来"的测试里暴露：

| # | 缺陷 | 症状 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | 全球风恒为 0 | 八层风速 0.0 m/s、引导气流 (0,0) | 气压梯度只来自本地生物群系温度；同一种群系铺满全场时梯度恒为 0，且缺少量级标定 | 加赤道—极地温差（−38 K·lat²）+ `GEO_SCALE=0.003`，把"512 格当 512 m"的尺度失真拉回真实量级 |
| 2 | 云量恒为 0 | "降水条件下能成云"失败；HUD 永远 0% | `swap()` 放在 `relaxMoisture` 之后，把地表强迫/凝结结果覆盖回平流前的旧值 | 平流后立即 `swap()`，之后所有就地修改才会被保留 |
| 3 | 风暴超速约 6 倍 | 40 tick 位移 199.8 格（≈100 格/秒） | 漂移量被直接加到速度上，而阻尼 0.985 的稳态增益是 1/0.015≈67 | 漂移项乘 `(1−RESISTANCE)`，稳态速度才等于漂移速度本身 |

第 2 个尤其值得记：它让**整条强迫链静默失效**，而场依旧"看起来正常"（无 NaN、量级合规）。
如果没有"降水必须成云"这条行为断言，它会一直潜伏到玩家发现"下雨但没有云"。

这是本轮新增的诊断入口。没有它，"场是不是发散了"只能靠肉眼。

## 10. 性能预算

| 项 | 频率 | 规模 | 实测 / 说明 |
|---|---|---|---|
| 本地场单步 | 3 tick | 2048 格 × 10 段 | **690 µs/步**（含 24 步预热）→ 均摊 ≈ 0.24 ms/tick |
| 速度投影 | 同上 | 8 迭代 × 2 色 × 2048 | 占单步约 2/3；从 12 降到 8 次迭代，散度仍只有 7e-4 |
| 静力学积分 | 同上 | 128 列 × 8 层 `exp` | 1024 次 exp/步，可忽略 |
| 全球场步进 | 20 tick | 512 格 | 8×8 列，含 64 次生物群系查询（仅重建时） |
| 地形风 | 按列，10 tick 缓存 | ≤ 49 次/破坏扫描 | 只有 miss 才 `getHeight` |
| 网络 | 探针 1 Hz / 图层按请求 | 44 B / ~300 B | 图层不主动推送 |

均摊：0.24 ms/tick 对 50 ms 的 tick 预算是 **0.5%**，与"一台中等规模的红石机器"同量级。

不做的优化（有意）：`project()` 不做收敛判定、不做多重网格。**固定开销**才能保证
"服务器卡的时候它不会更卡"——这一点比多迭代几次重要。

## 11. 已知限制

1. **网格是局地的**：玩家快速移动（鞘翅/传送）时网格会重建，重建那一帧温度场是气候态初值，
   会看到一次"重置"。目前用 2 格滞回 + 首帧不步进来掩盖，但跨维度仍可见。
2. **垂直分辨率粗**：8 层 × 48 格，单个雷暴的砧状云顶（~12 km）落不进网格，靠全球层补。
3. **地形风只看高度图**：悬空平台、桥、洞穴不会产生遮蔽，只有"地面高度"参与。
4. **纬度是伪造的**：`z / 3000 × 80°`，和真实球面无关，只是为了"南北移动时科氏力会变"这个手感。
5. **没有湿对流参数化**：CAPE/CINH 仍在 `Thermodynamics` 里独立算，没有反馈进网格的浮力项。
