# v0.3.2 · CO₂ 示踪场、机器排放与疾病兼容层

> 需求：把大气场从"温湿压风氧"扩展到**可输送的污染物**。机器耗氧 → 排 CO₂/有害物质 →
> 随半拉格朗日平流扩散 → 环境外观变化 → 人体中毒。优先直接套用现成 mod，用兼容层适配。

---

## 1. 关键决策：不重造污染场和疾病系统

调研结论（1.20.1 Forge）：

- 整合包已装 **Pollution of the Realms**（mod id 约 `adpother`）：机器燃烧 → 碳/硫/粉尘污染 →
  随风漂移的污染云 → 按浓度给原版效果（碳 >30% 挖掘疲劳 … >90% 凋零），已兼容 Create / GTCEu。
- **BioForge V2**：唯一有正式 Java addon API 的疾病框架（空气/环境传播、潜伏期、免疫、疫苗），但玩法重。
- **Plague Delight** 要求 Forge 47.4.x，与整合包 47.2.0 不兼容，排除。
- 原版效果载体：`nausea`(反胃) / `blindness` / `poison` / `wither` / `weakness` / `mining_fatigue`。

**选定方案**（用户拍板）：

1. **PMWeatherLite 自建 CO₂ 示踪场**，用点名的**半拉格朗日平流**输送，机器耗氧 → CO₂ 源项；
   CO₂ 驱动雾色浑浊、能见度下降、雷达新增图层。
2. **生病复用 PoT 的原版效果**：PMWeatherLite 的 CO₂ 中毒阈值**对齐 PoT 的碳污染分级**，
   两套系统给出一致结局，不打架；KubeJS 补强"缺氧黑视"表现。

分工原则：PMWeatherLite 负责"场 + 平流 + 观测 + 外观"，PoT 负责"疾病表现"，两边用同一套原版 effect 语言互通。

## 2. 数据层：CO₂ 示踪场

`AtmosphereGrid` 新增：

| 字段 | 维度 | 含义 |
|---|---|---|
| `co2[]` / `co2N[]` | 2048 格，双缓冲 | CO₂ 体积分数；背景 `4e-4`（400 ppm），上限 0.12 |
| `emission[]` | 256 列 | 每列排放源强度 0..1 |

**源项**（`applySurfaceForcing`）：
- 检测"燃烧中的机器/火"：`BlockStateProperties.LIT == true`（覆盖熔炉/烟熏炉/高炉及用 LIT 的 mod 机器），
  另有火/熔岩/岩浆块。用属性而非硬编码方块表 → Create / GTCEu 机器自动接入。
- 每步：`burn = emission * 0.0045 * dt`；`o2 -= burn`，`co2 += 1.6 * burn`（近似 1:1 摩尔，游戏化放大）。
- 开阔天空的 CO₂ 向背景松弛（通风），否则会永久累积。

**平流**（`advect`）：CO₂ 与温湿氧云**共用同一条半拉格朗日回溯轨迹**
`（gx,gy,gz) = (x,y,z) - (u,v,w)·dt/Cell`，三线性采样上游值。排放源下风处自然形成羽流。

**对外入口**：
- `Probe.co2` —— 1 Hz 探针包带到客户端。
- `columnCo2(wx,wz)` —— 整列最大值（雷达图层用）。
- `injectEmission(wx,wz,strength)` —— **兼容层接线点**：KubeJS / 其他 mod 的耗氧机器可直接登记排放，
  不必改方块表。
- `configure(co2Enabled, machineEmissions)` —— 开关；全关回到 v0.3.1 行为。

## 3. 表现层：环境污染外观

| 位置 | 改动 | 光影包下 |
|---|---|---|
| `ClientRadarCache` | 探针包写入 `ClientVisualState.co2` | 照常 |
| `AtmosphereLayer.applyFog` | CO₂ 污染再收能见度（最多额外 -45%），独立于风暴 | 让路（Iris 自算雾） |
| `AtmosphereLayer.applyFogColor` | 污染天幕：低饱和黄褐烟霾，强度随 CO₂ | 让路 |
| `RadarScreen` | HUD 增 CO₂ ppm 读数；图层 8 = CO₂（ppm） | 照常 |

`ClientVisualState.pollution()` 把 CO₂ 归一到 0..1（1% 起、5% 封顶），供所有视觉层共用。

## 4. 健康层：与 PoT 对齐的中毒分级

`AtmosphereManager.effectTick()` 每秒检查玩家，CO₂ 阈值**对齐 PoT 碳污染**：

| CO₂ 体积分数 | 约 ppm | 原版效果 | 对应 PoT 碳级 |
|---|---|---|---|
| ≥ 1.0% | 10000 | 挖掘疲劳 | >30% 碳 |
| ≥ 2.0% | 20000 | +虚弱 | >50% 碳 |
| ≥ 3.0% | 30000 | +反胃 +失明 | >70~80% 碳 |
| ≥ 5.0% | 50000 | +中毒 +凋零 | >90% 碳 |

- 全部用短时、隐藏粒子的 `MobEffectInstance`，离开污染区自然消退。
- 开关 `co2HealthEffects`；与 `oxygenEffects` 独立（低氧关掉不影响 CO₂ 中毒，反之亦然）。
- 阈值集中为常量，便于按 PoT 实测值微调。

## 5. 兼容层接线（给"直接套用"留口子）

- **PoT（已装）**：不硬依赖。两套系统用同一批原版 effect 和相近阈值 → 行为一致。
  若后续要读 PoT 的污染值做双向同步，可在 `injectEmission` / `probe.co2` 上桥接。
- **KubeJS**：`injectEmission` 是公共入口；服务器脚本里检测到耗氧机器即可登记排放。
- **BioForge（可选，未装）**：若要具名疾病，写薄 addon 在 CO₂ ≥ 阈值时调用其 addon API 施加病原体。

## 6. 开关与向后兼容

`ServerConfig` 新增 3 个开关，默认全开：

| 开关 | 作用 |
|---|---|
| `co2System` | CO₂ 场总开关；关 = v0.3.1 行为 |
| `machineEmissions` | 是否把 LIT 机器/火当排放源 |
| `co2HealthEffects` | CO₂ 中毒后果 |

协议版本 `"2" → "3"`（探针包加 co2 字段）。既有命令/数据结构/雷达图层 0-6 保持不变，新增图层 7。

---

## 7. 性能与验证

- CO₂ 场：2048 格各多一次三线性采样 + 一次 swap，稳态单步增量约 5~8%，仍在 1500 µs 预算内。
- 自检新增 4 项（初值为背景 / 排放成羽流 / 有界 / 下风平流），覆盖"swap 漏 co2N"这类静默缺陷。
- 验证：`/pmwlite atmoscheck` 全绿；雷达切到图层 8 看 CO₂；燃烧熔炉后下风处 ppm 升高。
