# PMWeather → 星海纪元 1.20.1 全覆盖版：移植工程方案（兼容光影版）

> 目标：把 ProtoManly's Weather（下称 PMWeather）的"风暴体验"移植进本包
> （**Minecraft 1.20.1 + Forge 47.2.0 + Oculus 1.8.0 + Embeddium**），**且必须兼容光影**。
> 本文基于 **官方 0.17.20 源码逐行分析 + Modrinth API 实查**，不是凭感觉写的。
> 结论先行：**搬源码不可行；"兼容光影"更是否决了照搬渲染层的路线。唯一正确的架构是——云交给光影包，mod 只做物理与破坏。**
> 分析日期：2026-11-18。源码快照：`pmweather-1.21.1-0.17.20-alpha.jar`（Modrinth `TfCsmTLI`）。

---

## 〇、一句话结论

PMWeather 的"光追观感"来自 1160 行 GLSL 体积云 raymarcher，跑在 **Veil** 的后处理管线上；
而 Veil **在 1.20.1 Forge 上根本不存在**，且 Veil 后处理与光影天生互斥（这正是原版要关光影的原因）。
所以：

- **不能"搬"**：改配置/写兼容层做不到，源码级移植等于换掉整个渲染后端。
- **不能既要原版光追又要光影**：这两个在架构层面就是抢同一条渲染管线，不可兼得。
- **能做到的正解**：逻辑层（物理/风暴/破坏）移植重写，**视觉层交给 Oculus 光影包的体积云**，
  用几何体粒子表现龙卷风。这样云是光影画的、 tornado 是 mod 画的，互不抢管线 → **真正兼容光影**。

## 一、PMWeather 到底是怎么"做到"的（源码级解剖）

先把对手研究透，才知道要搬什么、要丢什么。通读 222 个 java + 2242 行 GLSL 后的机制链条：

### 1.1 渲染：全屏后处理 + 光线步进（"光追观感"的来源，也是光影冲突的根源）

它**不是粒子**，而是在屏幕空间逐像素做体积积分（raymarching）：

- 入口：`shaders/PMWPostShader.java` → `shaders/post/VolumeShader.java`、`SkyShader.java`。
- 通过 **Veil 的 `PostProcessingManager`** 注册两个后处理管线：
  - `assets/pmweather/pinwheel/post/sky.json`：`renderStage: after_sky`，`replace: true`
  - `assets/pmweather/pinwheel/post/volumes.json`：`renderStage: after_weather`，`replace: true`
- 管线用 **Veil 专有 stage 类型** `veil:blit`、`veil:depth_function`。
- 着色器：`pinwheel/shaders/program/clouds.fsh`（**1160 行**核心 raymarcher）、`sky.fsh`、`volume_finalize.fsh`，
  另有 14 个 include（storms/supercell.glsl 286 行、noise、lighting、wind、sway…）共 2242 行。
- 每帧灌入 uniform：`MAX_STORMS 16`、`MAX_POINT_LIGHTS 32`、`MAX_SMOKE 64`，
  以及每个风暴的 `position / spin / energy / windspeed / width / stage`（见 `VolumeShader.pre()`）。
- 用 `sampler3D Noise3DSampler` 三维噪声纹理 + Veil 私有 GLSL 预处理：
  ```glsl
  #include veil:space_helper
  #veil:buffer veil:camera VeilCamera
  ```
- 光照：`lighting.glsl` 做太阳/天空散射，云边缘透光、超级单体遮蔽都是体积积分算出来的。

> ⚠️ 注意 `replace: true`：它直接**替换**了天空和天气阶段的正常渲染。光影包恰恰也要在这两个阶段画自己的体积云和光照——这就是互斥的技术根源，不是配置能调好的。

### 1.2 物理：噪声场驱动的热力学大气模拟（这部分与平台无关，可移植）

- `ThermodynamicEngine.java`：`SimplexNoise` + FBM 生成**温度场**；海温 SST 由群系温度+湿度+昼夜正弦+6 阶 FBM 算出；
  `getPrecipitationType()` 沿垂直方向采样温度，判定 雨/雪/雨夹雪/冻雨。
- `WindEngine.java`：FBM 生成**背景风场** `getWind()`，叠加风暴环流与龙卷风涡旋；
  `getSwirl()` 算涡度，`FireIntensityCache` 管野火强度。
- `RiskEngine.java`：环境风险引擎——风暴在哪生成、能否升级，受群系/海温/季节影响。
- `Storm.java`：单个风暴状态机——位置/速度/风速/宽度/能量/stage，`rankineFactor=4.5`（Rankine 涡旋模型），带子涡旋列表。
- `Vorticy.java`：子涡旋，绕中心按 `angle += wind/300` 旋转，模拟多涡旋龙卷。
- 四种风暴（`StormTypes.java`）：`supercell` 超级单体、`squall` 飑线、`cyclone` 气旋、`fire_whirl` 火龙卷。

### 1.3 破坏：按风速阈值拆方块（可移植）

- `ServerConfig.blockStrengths`：每种方块的"被吹坏风速"（树叶 50-65、羊毛 60、箱子 120、强化玻璃 130-140）。
- `BLACKLISTED_BLOCKS / BLOCKTAGS`：基岩类/泥土/沙/冰设为不可破坏。
- 龙卷风触地后按风速扫过区块，方块变成 `entity/MovingBlock.java` 飞行实体，绕漏斗旋转并造成伤害。
- 配套方块：强化混凝土/玻璃、雷达、风速计、气象站、警报器、探空气球。
- 自带**季节系统**（`seasons/`）——所以 `mods.toml` 把 `sereneseasons` 标为 `discouraged`。

### 1.4 平台锁死（逐条来自 `neoforge.mods.toml`）

```toml
minecraft   required  [1.21.1]          # 硬锁 1.21.1
neoforge    required  [21.1.229,)       # 硬锁 NeoForge
veil        required  [4.2.1,)  AFTER   # ← 渲染命脉，NeoForge 专属
sodium      incompatible (,0.8.12-beta.1)
distanthorizons incompatible (,3.3.0)
immersive_portals incompatible          # 会闪烁
sereneseasons discouraged               # PMWeather 自带季节
```
可选兼容 mixin：`create` / `sable` / `powergrid` / `iris` / `sodium`。

> 关于那两个 Iris mixin：`WorldRenderingPhaseMixin` / `SodiumProgramsMixin` 只把 `swayingCutout`（植被摇曳）
> 这一种自定义 RenderType 映射到 Iris 的 `TERRAIN_CUTOUT` 阶段。**它解决的是植被在光影下的渲染阶段映射，
> 不是让体积云与光影共存**。Modrinth 官方页至今仍写 "THIS MOD DOES NOT WORK WITH SHADERS"。别被 mixin 名字误导。

## 二、硬障碍清单（查证结果，逐条）

| # | 障碍 | 查证结果 | 影响 |
|---|---|---|---|
| 1 | **Veil 不存在于 1.20.1** | Modrinth API：Veil 109 个版本**全部 1.21.1**，仅 Fabric/NeoForge，**无 1.20.1、无 Forge** | 致命：后处理/3D纹理/相机 uniform 体系要重写 |
| 2 | **光影互斥（本次新增硬约束）** | 原版 `replace:true` 抢占 after_sky/after_weather，与光影包抢管线；官方声明不兼容光影 | 致命：照搬渲染层永远无法满足"兼容光影" |

| 4 | **MC 版本 API 断裂** | 1.21.1→1.20.1：`ResourceLocation`、`RenderType`/`VertexFormat`、`PostChain`、注册表构建方式全变过 | 渲染代码大面积不兼容 |
| 5 | **GLSL 是 Veil 方言** | 着色器用 `#include veil:space_helper`、`#veil:buffer veil:camera`、`sampler3D` | 需在 Iris/Oculus 侧重写预处理与 uniform 注入 |

| 7 | **许可** | `license="All Rights Reserved"` | 不能直接重分发其 jar/源码/着色器原文；只能独立重写 |

> 辟谣：9minecraft、mcpeuday 等站声称"PMWeather 有 1.20.1 Forge 版"——**假的**。
> 官方 64 个版本 100% 是 1.21.1 NeoForge。别从那些站下 jar，多为盗链/捆绑。

## 三、"兼容光影"重新定义了架构：把渲染权交还给光影包

这是本次追加要求带来的**核心结论**。原版失败的原因不是"光影和光追不能共存"，而是
"**两个 mod 都想画天空，抢同一条管线**"。反过来做就能共存：

```
        原版 PMWeather（互斥）              推荐架构（兼容光影）
┌─────────────────────────┐      ┌─────────────────────────────┐
│ Veil 后处理画体积云      │      │ Oculus 光影包画体积云/光照   │
│ replace 掉 after_sky    │ ←冲突→│ Complementary/Cristal/...   │
│ 光影包也要画云 ─────────┘      │ after_sky / after_weather   │
│                                ├─────────────────────────────┤
│ mod 只管风暴物理+破坏     │      │ 新 mod 只管物理+风暴状态+破坏│
│ 光追云与破坏绑定在一起    │      │ 用实体/粒子/音效表现 tornado │
└─────────────────────────┘      │ （几何体走正常管线，不抢后处理）│
                                 └─────────────────────────────┘
                                        两者互不干扰 = 兼容光影
```

### 3.1 已验证的可行性依据

- 本包已有 **Oculus 1.8.0 + Embeddium 0.3.31**（官方查证：Oculus 是 Iris 的 Forge 移植，Iris 官方不支持 Forge）。
- **Cristal Shaders** 明确写明"developed and tested with Forge 47.4.10, Embeddium 0.3.31, Oculus 1.8.0"，
  且自带 volumetric cumulus clouds / cirrus / 逐日变化的云量。
- **Complementary / BSL / Aureveil / Photon Engine** 在 1.20.1 Oculus 下都带体积云
  （Aureveil、Photon 明确要求 Oculus ≥1.7 + Embeddium，本包满足）。
- 光影包能读取游戏天气状态（Cristal 的闪电闪光/积雪/极光依赖 Iris/Oculus 提供的天气数据）——
  意味着 mod 只要正确驱动原版天气/光照状态，光影包就会跟着变天。

### 3.2 风暴在光影下如何"看得见"（三种不抢管线的手段）

体积云交给光影后，龙卷风本体的视觉用这些方式实现——都是几何体/状态，不碰后处理：

1. **实体/粒子几何**：`MovingBlock` 飞行方块、碎片、沙尘用正常实体渲染管线，光影会正常给它们打光/投影。
2. **驱动原版天气状态**：风暴临近时提升 `rainStrength`、触发闪电 → 光影包的暴雨天色/闪电自动响应（Cristal 已验证依赖此数据）。
3. **客户端提示**：本包已有的 `02_storm_shader_notice.js`（字幕提醒）+ `03_tornado_broadcast.js`（全服播报）继续保留。

> 代价：不会有 PMWeather 那种"漏斗本身是体积光追云"的观感。但这是"兼容光影"必须付的代价，
> 换来的是光影全效（阴影/反射/体积光/体积云）全开且不掉链子。

## 四、三条路线（在"兼容光影"约束下重新排序）

### 路线 A：功能等价重写 + 光影包渲染（★唯一推荐）
- **云/光照**：直接用本包 Oculus 光影包的体积云（Complementary/Cristal 等），零开发成本、天然兼容光影。
- **逻辑**：新写 Forge 1.20.1 mod，移植 `ThermodynamicEngine`/`WindEngine`/`Storm`/`Vorticy`/`RiskEngine`
  的**纯 Java 算法**（与平台无关，可近乎直译）。
- **破坏**：复用 `blockStrengths` 思路，Forge `BreakEvent` + 飞行方块实体。
- **作品形态**：原创 mod（换名规避 ARR），玩法≈PMWeather，风暴视觉由光影包提供，**光影全兼容**。
- 工作量：**中高**；**唯一同时满足"能跑在 1.20.1 Forge" + "兼容光影"的路**。

### 路线 B：NeoForge 1.20.1 折中
- NeoForge 有 1.20.1，但 **Iris 只支持 NeoForge 1.21.1+**（Iris 官方 FAQ），1.20.1 仍得靠 Oculus。
- Veil 依旧没有 1.20.1 → 渲染层还是重写；且整个包要换底座，背离"兼容本包"。
- 结论：**淘汰**。

### 路线 C：硬移植（在光影要求下判死刑）
- 需把 109 个 Veil API 调用点、7 组 mixin、2242 行 GLSL 适配到 Forge 1.20.1。
- 即使做出来，它的 `replace:true` 后处理**依然和光影互斥**——要兼容光影还得把渲染层再推翻重写一次。
- 等于做两次重写，且 ARR 许可下不能分发成品。**淘汰**。

## 五、推荐路线 A 的最小可运行骨架

均按 **Forge 1.20.1 + Java 17（本机 JDK 17 + Gradle 8.14.2 已具备）** 设计。

5. 与原 Weather2 二选一（都管天气会冲突），写进 `README-冲突仲裁.md`。
6. 性能验收：光影全开 + 风暴时的帧率，按本包说明的"关闭顺序"调预设。

## 六、诚实的边界（必须说清）

- **不能**同时拥有"PMWeather 原式体积光追漏斗"和"光影全开"——架构上二选一，本方案选光影。
- **不能**逐帧达到 PMWeather 的观感；那是专用 GLSL + Veil 的产物，本方案是"玩法复刻、观感借光影包"。
- **不能**直接分发 PMWeather 的 jar/源码/着色器原文（ARR 许可）；本方案是独立重写。
- 路线 C（数人月级）超出单次对话可交付范围；骨架 + 算法层 + 分阶段计划是本次能给出的最大可落地成果。
- **零成本对照**：若诉求只是"光影下的震撼风暴"，可先把本包 Weather2 调到最强 + 换体积云光影包
  （Complementary/Cristal），光影全开直接见效，不必先写 mod。

## 九、极端天气系统重构（现实气象学对标，2026-11-18）

应要求把天气系统按现实气象学扩展。**完整设计见同目录 `极端天气系统设计.md`**（18 种天气的名称/形成条件/强度分级/持续时间/影响范围/视觉/影响全表）。

### 9.1 新增核心文件
- `weather/WeatherType.java`：把 **18 种现实极端天气**编码成枚举，每种带完整参数：
  名称、类别、形成条件、强度分级（CMA/NWS/EF/萨菲尔-辛普森）、最短/最长持续小时、
  核心/外围半径、生成稀有度、视觉环境表现、对人物交通建筑的影响。
- `weather/WeatherSystem.java`：全类型生成/持续/影响管理——按现实形成条件门控（海洋才生飓风、干旱才生沙尘、低温才生冬季降水），
  强度分级、持续时间包络（1 分钟龙卷 ~ 数周热浪）、寿命包络（渐强-峰值-衰减）、距离衰减、分类风场（气旋旋转/直线风辐散）。

### 9.2 18 种天气清单
强对流：超级单体、龙卷(EF0-EF5)、飑线、下击暴流、冰雹；
热带：飓风(1-5级)、温带气旋；
冬季：暴风雪、冰冻雨、雨夹雪；
沙尘：沙尘暴(浮尘→特强黑风暴)、火星尘暴(稀有天象)；
温度：热浪/热穹顶(黄橙红)、寒潮/极寒；
火天气：火龙卷、野火；
水文：山洪/暴洪、特大暴雨。
（原 PMWeather 仅 5 种，新增 12 种。）

### 9.3 与现实对齐的分级（已编码）
- 龙卷 EF0-5：65-85 / 86-110 / 111-135 / 136-165 / 166-200 / ≥201 mph
- 飓风萨菲尔-辛普森 1-5 级 + 热带低压/风暴
- 冰雹按直径：豌豆6mm→镍币18→25mm(强对流阈值)→高尔夫45→棒球70→葡萄柚100mm
- 沙尘暴按能见度：<10km浮尘 / <1km沙尘暴 / <500m强 / <50m特强黑风暴
- 高温黄/橙/红：≥35℃连续3天 / ≥37℃ / ≥40℃；寒潮24h降温≥8℃
- 冰冻雨积冰：<6 / 6-13 / 13-25 / >25mm 四级

### 9.4 命令
`/pmwlite list` 列出全部类型；`/pmwlite weather <TYPE>` 手动触发任意一种（调试/拍片）；
`/pmwlite summon`、`/pmwlite clear` 保留。所有类型共享"粒子+光影包出体积云"的兼容渲染原则。
